# Antigravity Tri-Plugin Autonomous Operating Directive

Whenever building any website, web application, feature, or performing any engineering task, the agent MUST route the work through the **Tri-Plugin Intelligence Engine** (Get Shit Done + Ralph Loop + CodeRabbit).

Never jump into ad-hoc, unstructured coding. Always follow the **Tripartite Decision & Execution Lifecycle**:

---

## 🧠 The 4-Stage Tri-Plugin Decision Loop

```
┌────────────────────────────────────────────────────────┐
│  Stage 1: GSD (Strategic Architecture & Scoping)       │
│  - Structures specs, requirements & UI design contract │
│  - Builds / updates PRD.md & .planning/ROADMAP.md      │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│  Stage 2: Ralph Loop (Disciplined Atomic Execution)    │
│  - Solves one task from PRD.md with fresh context      │
│  - Enforces premium UI/UX design (glass, gradients)    │
│  - Logs iteration progress to progress.txt             │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│  Stage 3: CodeRabbit (Quality, Security & Remediation) │
│  - Scans diff for security, performance & a11y         │
│  - Auto-remediates any detected flaws before checkoff  │
│  - Enforces zero regressions                           │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│  Stage 4: Next-Best-Action Synthesis ("Best Thoughts") │
│  - Evaluates remaining roadmap against vision          │
│  - Explains the strategic rationale for the next step  │
└────────────────────────────────────────────────────────┘
```

---

## 📋 Specific Plugin Responsibilities

### 1. GSD Phase (Planning & Architecture)
- Before writing code, ensure `.planning/PROJECT.md` and `PRD.md` exist.
- If the user asks for a website, specify:
  - Color palette, typography, visual aesthetic (dark mode, glassmorphism, smooth animations).
  - Component hierarchy and routing.
  - Numbered, verifiable task checklist in `PRD.md`.

### 2. Ralph Loop Phase (Iterative Execution)
- Pick the first unchecked item in `PRD.md` (`- [ ]`).
- Implement the code cleanly with high-grade visual craftsmanship.
- Run tests or visual verification.
- Append a timestamped log to `progress.txt`.

### 3. CodeRabbit Phase (Automated Code Review & Fix)
- Audit the newly generated code diff.
- Verify security, responsiveness across screen sizes, and performance (bundle size, semantic tags, zero dead code).
- Immediately fix any issues detected.
- Mark the task complete in `PRD.md` (`- [x]`).

### 4. Continuous Learning & Next Best Thought
- If any convention, design preference, or build quirk is discovered, record it using `/learn` into `.planning/learned-context.md`, `.coderabbit/learned-rules.md`, or `.ralph/learned-patterns.md`.
- Conclude each response with **"Next Best Thought"**: clearly explaining what was completed, why the next task was chosen, and the next strategic milestone.
